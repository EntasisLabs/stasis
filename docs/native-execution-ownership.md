# Native execution ownership and atomic completion

Review candidate for isolated undertaking `work-e2e8d519551b99d956eedbf656484a03`, based on `a7814f40c5c3ee2522d93f4ac47c1e216cc9bcf2`. This is a Stasis foundation change, not CI implementation, deployment, or sender acceptance. The CI undertaking and its `b87875ee` candidate are unchanged.

## Correction of rejected candidate `b78f9f6369b8`

A worker's local `Job` is only a carrier for its submitted native grant, not an authoritative publication specification. Completion and expired-lease recovery derive all metadata, incarnation, cycle, retry policy, counters and lineage from the canonical job before applying the explicit outcome. Memory does this under the same native lock. Surreal reads a canonical base and fences that base with native owner/epoch/version inside the publication transaction; any intervening control-plane save advances the version and cannot publish stale derived artifacts. Native heartbeat/progress/wakeup do not change specification or counters, and their effective values remain transaction-owned. The Surreal transaction updates only explicit outcome/transition fields, never replaces canonical identity/specification with caller content. Job, retained receipt, attempt and outbox agree on canonical lineage and transition counters. Receipt-first same-digest/conflict replay remains valid after deletion, cancellation, replacement or durable reopen.

`tests/native_identity_publication.rs` reproduces genuine-continuation stranding and canceled-predecessor edge materialization through forged local incarnation on memory and actual Surreal Mem. Its supplementary matrix covers success, fatal/retryable failure, deferral and native recovery with forged metadata/counters, derived attempt/outbox consistency, and actual SurrealKV graceful close/reopen. Exact commands, failures and final evidence are in `foundation-evidence/IDENTITY-PUBLICATION.md`. This does not authorize workers to change job specifications, perform migrations, accept or merge work, or prove power-loss durability.

## Authority and native boundary

`Job.execution_epoch` is issued atomically by native acquisition, including same-owner reacquisition. `Job.version` advances with native disposition/control transitions. `JobContext.execution_grant` captures job ID, native owner, epoch and processing version from the acquired native snapshot; a wrong-owner/non-active context captures no authority. Neither CI attempts, caller timestamps, nor a resource-lease fence can issue this grant. The compatibility `fencing_token` mirrors the execution epoch only: **it is not a resource-lease token**.

`JobStore.commit_execution(snapshot, outcome)` checks the complete grant, live lease and active state at the trusted native clock. There is no caller-selectable recovery bypass. Native `recover_execution(snapshot)` accepts only a fixed expired-lease failure and checks expiry/current disposition in the same boundary. Ordinary errors, typed results, retryable/fatal failures and deferred returns use these operations.

The boundary publishes the job disposition/result/provenance, diagnostic/evidence references, attempt, outbox event, retained digest receipt and lifecycle trigger together. In-memory views share one native state lock; there are no awaits between validation and canonical writes. Surreal uses a real transaction, including conditional acquisition/generation issuance and terminal publication. It rechecks native DB expiry after the writes before commit; a failure rolls everything back. Explicit DB transaction conflicts are retried at most four times with the identical outcome, not by rerunning the consumer. Transport/unknown errors are returned and can be resolved by exact idempotent replay.

Same grant and same outcome digest returns `AlreadyCommittedSameDigest`, without new writes, even after deletion/restart. A different digest returns `Conflict`; expired/superseded/canceled execution returns `Stale` (or a transaction error if expiry crosses the final transaction boundary). Epoch tombstones and receipts survive job deletion and normal retention. Delete/prune cannot remove a newly active reassignment based on an earlier terminal scan.

`save` is now control-plane optimistic CAS, not a completion API. Terminal publication through it is rejected; owner/lease-field rewrites are rejected. Running, heartbeat, progress, cancellation, operator failure, recovery and continuation materialization check coherent native authority/disposition. Owner-only heartbeat is retired: use `JobContext.heartbeat()` or `heartbeat_granted` with the native grant. Producer insertion accepts new enqueued jobs, never terminal output or caller lease ownership. Use `NewJob`, rather than hand-building authoritative `Job` snapshots.

## Staging, hooks and cancellation

Worker child jobs, continuation registrations and published events are noncanonical staging until a valid native outcome commits. Staging binds the full grant, is limited to 128 records per execution epoch, and is discarded on recovery/cancel/failure retirement/deletion; superseded versions cannot activate old records. Canonical continuation child creation and its disposition are one native conditional transaction, with deterministic child identity and parent epoch/version checks.

Committed lifecycle triggers are retained in the native receipt journal and replayed through `replay_lifecycle`; asynchronous hook errors never resave or downgrade the job. `on_lifecycle_committed(job, event, idempotency_key)` receives a stable key across retry/restart, including through typed and builder delegates. Native trigger creation is exactly once; delivery is at least once. **External side effects must deduplicate that key in their own persistent sink.** Arbitrary external effects cannot participate in Stasis's transaction. Legacy `on_lifecycle` is retained as a compatibility bridge, not a promise that unmodified external effects are exactly once. Register handlers before draining a restarted journal. A returned processing job ID, or a hook delivery error, must not be confused with the authoritative terminal result.

Cancellation and operator failure atomically revoke success authority, publish the disposition/trigger, cancel pending waits, and retain a native cleanup-only record for the retired grant. Cancellation wakeups target that epoch, not a newer same-owner attempt. `JobContext.acknowledge_cleanup(evidence)` records finalized descendant-reaping/log evidence idempotently. It cannot revive success, modify a newer job, or replace a different finalized acknowledgement. Inspect it with `cleanup_receipt(job_id, epoch)`.

A canceled automatic consumer return is retained as a cleanup/log **observation**, not successful output and not cleanup acknowledgement. Observations are bounded to eight returns of at most 65,536 bytes each. Only the explicit acknowledgement sets `acknowledged_at`. `Canceled` alone therefore never proves that descendants were killed or logs finalized. A remote/process supervisor must also react to native heartbeat/disposition rejection, not only a local watch channel.

## Compatibility and migration

Application import paths for `JobExecutionOutcome`, `JobLifecycleEvent` and the new execution contracts remain aliases of domain-owned types. Typed payload/output contracts are unchanged. Custom `JobStore` implementations must implement the atomic native operations, including `wake_execution`; default implementations fail closed, never emulate them with check-then-save. Hand-built `Job` literals now also require `incarnation` and `wakeup_pending`; producer code should use `NewJob`. Neither field may be assigned as execution authority by callers. Native insertion ignores caller incarnation and native save cannot rewrite it.

Use `InMemoryRuntime`/`SurrealRuntime` for coherent composition. Custom in-memory composition can use `native_outbox_store`, `native_attempt_store`, `native_continuation_store`, and `native_wait_store` from its job store. Do not mix unrelated default store instances and call them a single transaction boundary. Native attempt/outbox IDs are opaque epoch-qualified IDs; callers must not assume UUID syntax or derive grants by parsing them.

Migration requires a quiescent deployment; this assignment does not apply it:

1. Stop old workers/writers. Mixed old unconditional-save code can bypass the new protocol and is unsupported.
2. Backfill existing job rows with `execution_epoch = 0` and `version = 0` where absent. Historical results remain legacy/unfenced; do not invent a receipt or native grant for them.
3. Retire/re-enqueue legacy active epoch-zero leases under explicit operator policy before starting new workers. Epoch zero is never execution authority. Do not silently preserve a legacy Running lease as current native ownership.
4. Initialize the native schema/journals (`<job table>_execution_generation`, `_execution_receipt`, `_execution_cleanup`, `_execution_staged`, plus the existing attempt/outbox/continuation/wait tables) through the existing authorized database migration route. The new backend also initializes missing tables idempotently during insert/acquisition/control operations. Its native schema initializer backfills missing/zero `incarnation` on existing rows by advancing the retained generation above both its old value and any execution epoch, without inventing a receipt or granting an epoch-zero lease authority. It then runs `reconcile_legacy_identity`: epoch-zero leased/running rows are re-enqueued, a missing terminal cycle becomes 1 only when no receipt exists, and incarnation-zero waits plus unbound continuation floors bind to that parent or the initialization fails. Repeated initialization leaves issued incarnations unchanged. New jobs start with `wakeup_pending = false`. Historical control receipts remain retained; no ordinary retention may reset an incarnation counter. This migration is tested on actual Surreal Mem, including a pre-identity running fixture and a cycle-zero receipt refusal, and new issued identities are tested across actual KV reopen. It never changes credentials or existing permissions.
5. Never purge/reset generation tombstones with ordinary job retention. Keep committed receipts/cleanup evidence while their references or replay guarantees are required. Restore/rollback procedures must quiesce old workers too.

The native layer stages references/events, not an external artifact blob store. CI must seal immutable artifacts/logs under the captured grant and publish only their finalized refs through native completion. Its orphan collector must be bounded (for example, age-qualified batches), and delete only unreferenced staged blobs after checking retained receipts, attempts and pending outbox references; never infer orphanhood solely from a deleted job row. No external blob collector or process supervisor is implemented by this change.
